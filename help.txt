SAFE RECOVERY STEPS (RUN FROM THE PROJECT ROOT IN POWERSHELL)
------------------------------------------------------------
1. Rotate the keys above in their provider dashboards. Put the new values in
   the ignored .env.local file. Verify that DATABASE_URL and DIRECT_URL refer
   to the same intended Supabase project.

2. Load only the values needed for the Prisma commands into this PowerShell
   process, run the schema sync, then seed the admin. This does not print the
   environment values. Do not accept a Prisma data-loss warning without
   reviewing what it will remove.

   $names = @('DATABASE_URL','DIRECT_URL','INITIAL_ADMIN_EMAIL','INITIAL_ADMIN_PASSWORD','INITIAL_ADMIN_NAME','QR_SIGNING_SECRET')
   $previous = @{}
   try {
     foreach ($name in $names) {
       $previous[$name] = [Environment]::GetEnvironmentVariable($name, 'Process')
       $line = Get-Content '.env.local' | Where-Object { $_.StartsWith("$name=") } | Select-Object -First 1
       if (-not $line) { throw "Missing $name in .env.local" }
       $value = $line.Substring($name.Length + 1).Trim().Trim('"')
       [Environment]::SetEnvironmentVariable($name, $value, 'Process')
     }

     npm run db:push
     if ($LASTEXITCODE -ne 0) { throw 'Schema push failed. Keep the error output private of all connection strings and secrets.' }

     npm run db:seed
     if ($LASTEXITCODE -ne 0) { throw 'Database seed failed. Keep the error output private of all connection strings and secrets.' }
   }
   finally {
     foreach ($name in $names) {
       [Environment]::SetEnvironmentVariable($name, $previous[$name], 'Process')
     }
   }

3. If the seed says the admin already exists, it will not change that user's

4. Start Next.js. If it reports port 3001, either stop the other app using 3000
